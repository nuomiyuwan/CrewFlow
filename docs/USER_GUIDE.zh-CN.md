# CrewFlow 用户使用说明

适用版本：CrewFlow v1.4.1 及后续兼容版本。

CrewFlow 是一套桌面项目协作工具，用来管理项目录入、任务分派、流程节点、交付日历、人员账号、团队负载、项目归档和财务结算。它最初面向视频制作团队设计，但项目类型、任务工种、流程节点、状态和人员标签都可以自定义，因此也适合设计、广告、活动、工程、咨询、培训、软件交付、定制生产等行业。

## 1. 先理解 CrewFlow 的工作方式

CrewFlow 把日常工作拆成五层：

1. **项目**：一项需要持续推进并最终交付的工作。
2. **流程节点**：项目从开始到结束要依次经过的阶段。
3. **任务**：节点下面需要具体人员完成的工作。
4. **交付日历**：项目节点、截止日期和临时计划的时间安排。
5. **结算与归档**：项目完成后的合同、收付款、开票和资料留存。

不同行业只需要替换名称，不需要改变使用方法。

| CrewFlow 概念 | 视频制作示例 | 其他行业示例 |
| --- | --- | --- |
| 项目类型 | 短视频、纪录片 | 活动执行、软件实施、工程订单 |
| 任务工种 | 策划、拍摄、剪辑 | 设计、开发、采购、施工、讲师 |
| 流程节点 | 脚本、拍摄、粗剪、交付 | 需求、方案、执行、验收、交付 |
| 当前节点状态 | 进行中、等甲方反馈 | 等审批、等材料、暂停、已确认 |
| 项目经理 | 制片人、导演 | 客户经理、实施经理、项目负责人 |
| 外包任务 | 配音、演员、场地 | 供应商、施工队、自由职业者 |

## 2. 安装软件并选择工作模式

### 下载与安装

从 [GitHub Releases](https://github.com/nuomiyuwan/CrewFlow/releases) 下载与电脑匹配的压缩包：

- Apple 芯片 Mac（M1、M2、M3、M4 等）：选择 `macOS-arm64`。
- Intel 芯片 Mac：选择 `macOS-x64`。
- 64 位 Windows：选择 `Windows-x64`。

macOS 用户解压后，将 `CrewFlow.app` 放入“应用程序”文件夹。当前公开包没有 Apple 开发者签名，首次打开时如果被系统拦截，可在 Finder 中右键应用并选择“打开”，或到“系统设置 → 隐私与安全性”确认打开。

Windows 用户应先完整解压 ZIP，再从解压后的文件夹运行 `CrewFlow.exe`，不要直接在压缩包预览窗口中运行。如果 SmartScreen 提醒来源未知，请确认文件来自 CrewFlow 官方 GitHub Release 后再选择继续。

### 单人模式

适合个人、自由职业者、试用体验，或者只在一台电脑上管理全部工作的情况。

- 数据只保存在当前电脑。
- 不需要常驻主机，也不依赖局域网。
- 更换电脑时需要手动迁移数据文件。
- 同一份数据不适合多人同时使用。

### 团队模式

适合公司、工作室、部门或多人协作。

- 选择一台常开机作为团队主机，Mac 和 Windows 均可。
- 团队主机运行 CrewFlow Server，统一保存团队数据。
- 其他电脑通过局域网地址和访问密钥连接。
- 所有人看到同一套项目、任务、日历、人员和财务数据。
- 客户端每 2 秒同步增量变化，不会让多台电脑直接争抢同一个文件。

团队模式不要求 NAS。NAS 可以继续存放项目素材和文件，CrewFlow 的团队数据库应由常驻电脑上的 CrewFlow Server 管理。

## 3. 第一次使用

### 3.1 登录默认总控账号

干净安装默认提供一个总控账号：

```text
账号：zk
密码：123456
```

首次登录后，应立即进入左侧“账号管理”，修改总控用户名和密码。不要长期使用默认密码。

### 3.2 确定数据模式

点击左下角“工作模式”：

- 个人使用：选择“单人模式”。
- 团队主机：选择“团队模式”，然后点击“开启团队服务”。
- 普通团队电脑：选择“团队模式”，填写主机显示的服务器地址和访问密钥，再点击“测试连接”。

### 3.3 按顺序完成基础配置

建议总控按以下顺序初始化：

1. 在“选项管理”设置项目类型、任务工种、节点状态和流程节点。
2. 在“人员管理”录入员工姓名、状态和能力标签。
3. 在“账号管理”为需要登录的人员创建账号，并关联到对应员工。
4. 检查项目经理是否带有“项目经理”或“项目负责人”标签。
5. 创建一个测试项目，走通任务、日历、归档和财务流程。
6. 确认无误后再正式录入业务项目。

人员和账号是两类数据：人员代表实际员工，账号代表登录权限。建议先创建人员，再创建并关联账号。

### 3.4 随时查看使用说明

- 首次登录后的使用提示中，可以点击“完整使用说明”打开本手册。
- 进入软件后，可以随时点击左下角“使用说明”重新打开。
- 内置说明支持按章节浏览和关键词搜索，并且不需要连接互联网。

## 4. 跨行业初始化建议

### 视频、广告与设计

- 项目类型：短视频、宣传片、纪录片、品牌设计、活动物料。
- 任务工种：策划、文案、拍摄、剪辑、包装、调色、平面设计。
- 流程节点：需求对接、方案、执行、内部审核、客户审核、修改、交付、归档。

### 活动、会展与婚礼执行

- 项目类型：发布会、展览、年会、婚礼、路演。
- 任务工种：策划、设计、搭建、物料、主持、摄影、现场执行。
- 流程节点：需求、提案、报价、筹备、进场、执行、撤场、结算、归档。

### 软件、IT 与数字化实施

- 项目类型：系统开发、网站建设、软件实施、运维服务。
- 任务工种：产品、UI、前端、后端、测试、实施、运维。
- 流程节点：需求、原型、开发、联调、测试、上线、验收、维护。

### 工程、装修与定制生产

- 项目类型：装修工程、设备安装、定制生产、维修项目。
- 任务工种：设计、采购、生产、施工、质检、运输、安装。
- 流程节点：勘察、方案、报价、签约、备料、施工、验收、结算、归档。

### 咨询、培训与专业服务

- 项目类型：咨询项目、企业培训、审计服务、研究项目。
- 任务工种：调研、分析、顾问、讲师、报告、运营支持。
- 流程节点：需求确认、调研、方案、执行、成果评审、交付、复盘。

这些只是起始模板。总控和管理员可以在“选项管理”中删除不需要的普通选项，再添加本行业的名称。人员标签中的“项目负责人”“项目经理”“财务”“行政”是关键标签，会保留以维持角色和联动关系。

## 5. 角色与权限

| 角色 | 主要用途 | 常用功能 |
| --- | --- | --- |
| 总控 | 系统负责人 | 全局项目、任务面板、人员、账号、选项、团队、归档和财务 |
| 管理员 | 日常运营管理 | 项目、执行任务、人员、团队负载、日历和归档 |
| 项目经理 | 推进自己负责的项目 | 新建项目、初始任务分派、项目跟进、个人任务和项目日历 |
| 执行成员 | 完成被分配的工作 | 我的任务、相关日历、首页提醒和归档查询 |
| 财务 | 管理合同和收付款 | 财务结算、项目查询、交付日历、归档，也可以新建项目 |

重要规则：

- 项目详情中的“执行任务”只有总控和管理员可以持续编辑。
- 项目经理创建项目后，可以在立项设置中完成初始任务分派。
- 已归档项目只有总控和管理员可以再次编辑。
- 交付日历中，总控和管理员可以维护全部项目计划；项目经理只能维护自己负责的项目；执行成员和财务以查看为主。
- 财务模块默认只对总控和财务角色开放。
- 不要多人共用一个账号。每个人使用独立账号，记录和权限才清楚。

## 6. 新建一个项目

点击右上角“新建项目”，填写以下内容：

- **项目名称**：内部管理使用的名称。
- **甲方对接人**：客户联系人，选填。
- **项目路径**：项目资料或 NAS 文件夹位置，选填。
- **成片交付日期**：最终交付日期。
- **项目类型**：来自全局项目类型选项。
- **客户分类、客户单位**：均为选填，可使用已保存选项，也可自定义添加。总控或管理员可点击字段标题旁的编辑按钮，把名称改成“大客户”“合作单位”等适合本行业的叫法。
- **项目经理**：负责推进该项目的人。
- **优先级**：普通、重要或紧急。
- **任务工种**：本项目预计需要的工作类型。

客户名称和合同名称可以不同。项目创建后，财务可在“财务结算”的“甲方商务”中单独填写正式合同名称。

项目创建后会进入“设置交付和任务”：

1. 确认当前节点状态和流程节点。
2. 确认交付日期和节点名称。
3. 为每个任务选择内部人员或外包。
4. 内部任务选择团队成员；外包任务填写外包方名称。
5. 保存后，内部成员会在“我的任务”看到安排。

## 7. 项目中心

项目中心由项目列表和项目详情组成。

### 项目列表

用于快速比较：

- 项目名称、类型和客户。
- 项目经理与当前执行人员。
- 当前节点状态和流程节点。
- 交付日期。
- 正常、等反馈、有风险或已逾期状态。

项目较多时，列表区域内部滚动，顶部始终保持固定高度，便于查看详情。

### 项目详情

包含：

- 项目概览和资料路径。
- 一个主资料路径和按需增加的其他资料路径。
- 当前进度。
- 项目经理、节点状态、流程节点和下一节点。
- 执行任务及负责人。
- 每项任务可指定一个“完成实证资料”文件夹；系统只保存路径，不复制大型文件。
- 带箭头的完整流程顺序。

进度优先按任务完成比例计算；项目完成或归档后显示为 100%。

### 项目状态的含义

- **正常**：没有逾期，也没有被人工标为风险或等待。
- **等反馈**：项目状态被设为等反馈，或者节点状态为“等甲方反馈”“等内部确认”。
- **有风险**：管理人员明确把项目标记为“有风险”。
- **已逾期**：项目尚未归档，且交付日期早于今天。

“修改中”不会自动把项目判定为风险。风险应由管理人员根据项目实际情况主动标记。

## 8. 我的任务与任务面板

执行成员在“我的任务”中查看自己的工作：

- 项目和任务名称。
- 工种。
- 截止时间。
- 当前状态。
- 任务备注。

任务状态建议按实际进度维护：

- 未开始：任务已经分派，但尚未启动。
- 制作中：正在执行。
- 修改中：正在根据反馈修改。
- 已完成：工作已经结束。

总控看到的是全局任务面板，用于了解整个团队正在做什么，不代表总控本人参与任务。

任务面板支持按“全部、今天、本周、指定日期”快速筛选。指定日期只影响当前查看结果，不会修改任务日期。

## 9. 交付日历

交付日历会显示：

- 项目创建时生成的主要交付节点。
- 后续添加的项目计划。
- 中国法定节假日和调休上班日。
- 管理员设置的自定义日期标记。

在有权限的账号中，右键点击某一天可添加计划。日期自动使用被点击的日期，只需选择项目、填写计划名称和负责人。

已有计划可以长按后拖到当前月视图中的其他日期。松开后日期会立即更新，并联动项目下一节点、逾期和风险状态。单日计划较多时，点击“更多”可在独立列表中查看。

中国节假日数据只用于显示，不会写入项目，也不会改变项目日期。联网时会更新并缓存，暂时离线时使用本地缓存。

## 10. 团队负载

团队负载帮助管理人员判断任务是否集中在少数人身上。

- “任务”统计该成员在未归档项目中的未完成任务。
- 带“项目经理”标签的成员会显示当前负责的未归档项目数量。
- “风险”只在该成员关联到风险项目时出现；没有风险时不显示。
- 负载百分比综合未完成任务、负责项目、参与项目和修改中任务估算，上限为 100%。
- 负载环右侧显示该成员参与的未归档项目及其当前流程节点，项目较多时在卡片内滚动。

负载是排期参考，不是绩效评分。任务难度、工作时长和个人能力无法仅靠数量准确衡量，应结合实际沟通判断。

## 11. 人员、账号和选项管理

### 人员管理

人员记录包括姓名、在职状态、标签和关联账号。标签会影响项目经理候选、任务分派和团队负载展示。

删除人员前，系统会提示关联账号、未完成任务、项目和日历计划。历史项目中的姓名不会被强行清空，以保留记录。

人员离职后，项目中心会提示关联项目需要安排接替人员。

### 账号管理

创建账号时设置：

- 登录用户名和密码。
- 权限角色。
- 关联人员。

总控和管理员可以维护普通账号。不能删除当前正在使用的账号。

### 选项管理

总控和管理员可以维护：

- 项目类型。
- 任务工种。
- 当前节点状态。
- 流程节点。
- 人员标签。
- 新建项目中的两个客户字段名称。

修改选项时，系统会联动已有项目、任务、日历和人员标签。删除普通候选项不会直接清空历史记录。

客户单位如果已经关联项目，删除前必须指定替换单位；系统先更新关联项目，再删除旧单位。

## 12. 项目归档

当项目节点进入“归档完成”，或当前节点状态变为“已完成”，项目会进入“项目归档”。

归档页显示：

- 项目基本信息。
- 任务完成情况。
- 交付日期。
- 财务是否结清。
- 项目资料路径。
- 主路径之外的其他项目资料路径。

归档并不删除数据。只有总控和管理员可以重新编辑已归档项目。

## 13. 财务结算

财务模块以项目为单位建立独立商务档案。

### 项目结算列表

显示：

- 项目名称、客户、类型和项目经理。
- 合同金额。
- 已收和未收金额。
- 发票与结算状态。

### 甲方商务

可维护：

- 合同名称。
- 报价和比价状态。
- 合同状态。
- 开票状态。
- 甲方结算状态。
- 下次收款日期和款项。

项目名称用于内部管理，合同名称用于填写合同上的正式名称，两者互不覆盖。

### 收款和开票记录

使用“新增收款”和“新增开票”记录每一笔业务。金额会自动汇总到项目结算列表。发现录入错误时，应编辑或删除具体记录，不要只手工修改汇总金额。

### 外包商务

用于记录外包成本、外包发票、应付款、结算状态和跟进情况。项目归档后仍会保留财务记录。

## 14. CrewFlow 助理

点击右下角“CrewFlow 助理”可以整理当前账号有权查看的项目、任务、交付节点和工作提醒，也可以回答本说明书涵盖的软件使用问题。助理设置只保存在当前电脑，不会跟随团队项目数据同步。

### 本地规则

- 默认模式，无需联网，也不需要 API Key。
- 适合查询项目数量、任务状态、交付安排、风险和财务提醒。
- 不会把业务数据发送到外部模型。

### 在线 AI

适合分析自然语言、整理较长的聊天记录，支持使用 OpenAI 兼容接口：

1. 打开助理右上角“设置”。
2. 选择“在线 AI”。
3. 填写服务商提供的 API 地址、模型名称和 API Key。
4. 按需要选择是否提供项目摘要和财务摘要。
5. 点击“测试连接”，成功后保存设置。

API Key 使用 macOS 钥匙串或 Windows 系统凭据保护，只保存在当前电脑，不写入单人数据文件、团队 SQLite 数据库或 Git 仓库。项目上下文也只包含当前登录账号有权查看的摘要。

#### 使用 OpenRouter 免费模型

OpenRouter 提供 OpenAI 兼容接口，可以使用一个账号连接多种模型。只想免费体验的用户可以按下面的流程操作。

1. 打开 [OpenRouter 注册页面](https://openrouter.ai/sign-up)，使用 GitHub、Google 或邮箱注册并登录。
2. 进入 [API Keys 页面](https://openrouter.ai/settings/keys)，点击“Create Key”。
3. `Name` 填写 `CrewFlow`。
4. `Expiration` 可以保持 `No expiration`。
5. `Credit limit (optional)` 留空，`Reset limit every` 保持 `N/A`。
6. 点击“Create”，立即复制生成的 `sk-or-v1-...`。完整 Key 通常只显示一次，不要发给其他人。
7. 回到 CrewFlow 助理设置，选择“在线 AI”，按下面的内容填写：

```text
服务地址：https://openrouter.ai/api/v1
模型名称：openrouter/free
API Key：刚才复制的 sk-or-v1-...
```

8. 点击“测试连接”，测试成功后保存设置。

`openrouter/free` 只会在当前可用的免费模型中选择，不产生模型调用费用。也可以在 [OpenRouter 模型列表](https://openrouter.ai/models) 中选择特定模型，但模型 ID 必须明确带有 `:free` 后缀。不要填写没有 `:free` 后缀的付费模型，也不要启用付费模型作为备用线路。

免费模型适合个人试用和低频使用，通常存在每日调用次数少、高峰期响应慢或暂时不可用等限制。免费额度和模型列表可能随平台政策变化，请以 [OpenRouter 免费模型说明](https://openrouter.ai/docs/guides/routing/routers/free-router) 和 [OpenRouter FAQ](https://openrouter.ai/docs/faq) 为准。如果以后充值并使用付费模型，建议重新创建一个设置了消费上限的 API Key。

在线模型支持图片理解时，可以点击输入框旁的图片按钮、拖入图片，或直接粘贴剪贴板截图。支持 JPEG、PNG、GIF 和 WEBP，单张不超过 10 MB，每条消息最多 4 张、合计不超过 20 MB。

- 排期表、聊天截图和节点截图可以整理成交付日历候选，再由用户确认保存。
- 合同、报价等图片可以用于提取和总结信息，但当前不会直接填写财务字段。
- 图片只保留在当前助理会话中，不写入 CrewFlow 项目数据；发送后会由已配置的在线模型服务商处理。
- 当前入口只支持图片，不支持直接上传 PDF、Word 或 Excel 文件。此类文件可先截取需要分析的页面。

### 本地模型

适合已经在本机安装 Ollama 的用户：

1. 启动 Ollama 并提前下载一个模型。
2. 选择“本地模型”。
3. 服务地址通常为 `http://127.0.0.1:11434`。
4. 填写已下载的模型名称，例如 `qwen3:8b`。
5. 测试连接并保存。

本地模型的速度和效果取决于电脑配置及模型大小，不需要把数据发送到互联网。

### 从聊天记录提取日历计划

在线 AI 或本地模型模式下，可以粘贴项目群聊、会议记录或客户沟通内容，并说明“提取计划写入交付日历”。也可以在助理整理完信息后继续说“直接加进去”。助理会生成待确认清单：

- 核对项目、日期、工作内容和负责人。
- 可以修改、取消勾选或补充缺失信息。
- 点击“前往日历确认”，软件会跳转到交付日历并逐条打开已经预填的计划窗口。
- 再次核对后，由用户点击“确认并保存”才会正式加入交付日历。
- 重复或不完整内容会被跳过。

模型不能绕过界面直接修改项目。日历代填仍遵循原权限：总控和管理员可维护全部项目，项目经理只能维护自己负责的项目。

### 用自然语言打开操作窗口

在线 AI 或本地模型模式下，助理可以理解常见的项目操作，并把信息带入 CrewFlow 原有窗口：

- “帮我新建一个项目……”会打开预填的新建项目窗口。
- “把某项目改成有风险 / 等反馈 / 正常……”会预填项目健康度。
- “把某项目的流程节点改成甲方审核……”会预填项目流程和当前节点状态。
- “某项目改由张三负责……”会预填项目经理。
- “把某项目的设计任务分给张三……”会在项目编辑窗口中预填任务人员和状态。
- “把某条任务改成制作中 / 修改中 / 已完成……”会打开任务状态确认窗口。
- “天气城市改成上海……”会搜索城市并打开天气设置，由用户选择确认。
- “上班改成 9:30，下班改成 18:30……”会预填当前账号的上下班时间。
- “打开交付日历 / 项目中心……”会跳转到当前账号有权访问的页面。
- 包含明确项目、日期和节点的消息会生成交付日历候选。

助理继承当前登录账号的可见范围和编辑权限，只负责识别意图、匹配当前账号可见的项目、任务与人员并预填表单。用户可以继续修改或取消，只有点击窗口中的确认按钮后数据才会保存。无法操作的项目、已归档项目以及超出当前账号权限的操作不会执行。删除项目、删除人员、账号密码、财务金额、API Key、数据导入和清空等敏感操作不通过助理执行。

## 15. 团队模式部署

### 15.1 在常驻电脑开启服务

1. 确保常驻电脑与其他员工电脑处于同一局域网。
2. 打开 CrewFlow，登录总控账号。
3. 点击左下角“工作模式”，选择“团队模式”。
4. 点击“开启团队服务”。
5. 等待状态显示“运行中”。
6. 复制界面显示的局域网地址和访问密钥。

后台服务安装成功后，CrewFlow 窗口和终端可以关闭。常驻电脑需要保持开机并登录到安装服务的系统用户。

### 15.2 其他电脑连接

1. 安装并打开同版本 CrewFlow。
2. 在“工作模式”选择“团队模式”。
3. 填写主机地址，例如 `http://HOST_LAN_IP:8787`。
4. 填写主机生成的访问密钥。
5. 点击“测试连接”。
6. 连接成功后再登录团队账号。

### 15.3 VPN 和虚拟网卡

常驻电脑同时开启 VPN 时，CrewFlow 可能显示多个候选地址。优先选择真实局域网网卡地址，而不是：

- `127.0.0.1`，它只能本机访问。
- VPN 或虚拟网卡地址。
- 与其他员工电脑不在同一网段的地址。

如果候选地址不确定，可以在另一台电脑浏览器中访问 `http://主机IP:8787/health`。能正常返回服务状态的地址才可使用。

### 15.4 防止重复主机

同一团队只能由一台电脑开启团队服务。如果局域网中已经检测到其他主机，本机的开启按钮会被禁用，并显示已开启电脑的 IP。

### 15.5 从单人数据迁移到团队

只有在首次建立团队库时才使用“导入本机数据到团队库”。团队已经开始正式使用后，不要从其他电脑反复导入旧单人数据，以免把过时内容带入团队库。

## 16. 数据位置与备份

### 单人模式

macOS：

```text
~/Library/Application Support/CrewFlow/crewflow-data.json
```

Windows：

```text
%APPDATA%\CrewFlow\crewflow-data.json
```

### 团队模式主机

macOS：

```text
~/Library/Application Support/CrewFlow Server/crewflow-team.db
```

Windows：

```text
%APPDATA%\CrewFlow Server\crewflow-team.db
```

团队服务会在同一数据目录维护 `backups` 备份文件夹。具体路径也会在“工作模式”的“数据文件位置”中动态显示，可直接打开目录。

建议：

- 定期备份整个 `CrewFlow` 或 `CrewFlow Server` 数据目录。
- 手工复制正在使用的团队数据库前，先停止团队服务；日常恢复优先使用系统生成的备份。
- 不要把 SQLite 数据库放到 SMB/NAS 共享目录供多人直接打开。
- 不要把访问密钥公开到群聊以外的公共网页或代码仓库。
- 替换或升级 `CrewFlow.app`、`CrewFlow.exe` 不会自动删除上述数据目录。

## 17. 软件更新

CrewFlow 会检查 GitHub Latest Release。发现新版本时，左上角版本号附近会出现更新提示，点击后进入下载页面。

团队更新建议按以下顺序：

1. 备份团队主机数据。
2. 先更新常驻主机上的 CrewFlow。
3. 重新启动或修复团队服务，确认状态正常。
4. 再更新其他员工电脑。
5. 测试登录、项目读取和保存。

新旧客户端可以短期混用，但涉及数据结构或团队同步调整的版本不应长期混用。发布说明如果要求升级主机，应优先执行。

macOS 更新时，用新版 `CrewFlow.app` 替换旧版即可。Windows 解压新版后，从新版目录运行 `CrewFlow.exe`。不要把新版文件零散覆盖到旧目录。

## 18. 常见问题

### 无法登录

- 确认使用的是当前数据模式下的账号。
- 团队账号修改后，需要等待客户端同步或重新连接。
- 检查大小写、空格和输入法状态。
- 忘记总控密码时，不要直接删除数据库，应先备份数据再联系维护人员处理。

### 团队数据读取失败或显示 502

- 确认常驻电脑开机且团队服务正在运行。
- 在主机“工作模式”中点击“刷新状态”或“修复/重启服务”。
- 确认客户端填写的是局域网地址，不是 `127.0.0.1` 或 VPN 地址。
- 检查 Windows 防火墙或安全软件是否拦截 8787 端口。
- 确认访问密钥与主机显示内容一致。

### 修改时提示数据已被其他电脑更新

说明其他电脑刚刚保存了新数据。CrewFlow 会先同步最新版本，请重新执行刚才的操作。这样可以避免后保存的旧数据覆盖别人刚完成的修改。

### 新建项目后日历没有显示

- 检查交付日期是否正确。
- 检查当前日历查看范围。
- 确认项目没有被筛选或归档。
- 团队模式下等待同步完成后刷新查看。

### 为什么项目显示有风险

“有风险”来自项目的人工风险标记；交付日期已过则显示“已逾期”。任务处于“修改中”不会自动判定为风险。

### 为什么团队负载很高

负载会综合未完成任务、项目经理负责的项目和修改中任务。它用于发现工作集中，不代表实际工时，也不用于自动考核。

### 为什么项目经理无法出现在候选列表

在“人员管理”中确认该人员：

- 状态为“在职”。
- 带有“项目经理”或“项目负责人”标签。
- 账号已正确关联到该人员。

### 为什么不能删除客户单位

该单位可能仍被活动项目或归档项目使用。先按提示指定替换单位，系统更新相关项目后才会删除旧单位。

## 19. 推荐的日常管理习惯

- 每个真实人员使用独立账号。
- 项目经理每天维护节点状态，执行成员及时维护任务状态。
- 重要反馈、审批、验收和收款日期放入交付日历。
- 风险只在确有风险时标记，并在解决后恢复正常。
- 项目完成后及时归档，但不要把归档当作删除。
- 财务逐笔录入收款和开票，不只记录汇总数。
- 每周检查一次团队负载和逾期项目。
- 每次软件升级前备份团队主机数据。
