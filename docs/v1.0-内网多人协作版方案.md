# v1.0 内网多人协作版方案

## 目标

把当前单机内测版升级为公司内网多人协作版。

目标效果：

- Mac 和 Windows 客户端共用同一套数据
- 多人同时打开 App 后能实时看到项目、任务、日历、财务变化
- 人员、客户、权限、账号不再写死在客户端
- 数据保存在公司内网，不走公网

## 推荐架构

```text
群晖 NAS / 内网电脑
├─ 后台服务
├─ 数据库
└─ 实时同步通道

员工电脑
├─ Mac 客户端
└─ Windows 客户端
```

客户端只负责界面和操作，所有数据读写都通过后台服务完成。

## 不建议的方式

不建议让所有客户端直接读写 NAS 上同一个 `json` 或 `sqlite` 文件。

原因：

- 多人同时保存容易覆盖
- 网络中断可能导致写入失败
- 实时同步难做
- 权限和审计难做
- 后续扩展困难

## 后台模块

1. 登录与账号
   - 账号
   - 密码
   - 角色
   - 在职状态

2. 人员管理
   - 人员名称
   - 岗位标签
   - 是否在职
   - 可否担任项目经理

3. 客户单位
   - 省份
   - 地级单位
   - 自定义客户

4. 项目中心
   - 项目基础信息
   - NAS 路径
   - 项目经理
   - 当前状态
   - 当前阶段
   - 归档状态

5. 任务系统
   - 工种
   - 执行人
   - 外包备注
   - 状态
   - 截止时间

6. 交付日历
   - 项目节点
   - 日期
   - 负责人
   - 编辑记录

7. 财务结算
   - 合同金额
   - 报价文件
   - 比价文件
   - 合同文件
   - 开票
   - 收款
   - 外包成本
   - 外包结算

8. 实时同步
   - 项目变更推送
   - 任务变更推送
   - 日历变更推送
   - 财务状态变更推送
   - 人员变更推送

## 数据库建议

优先级：

1. PostgreSQL：更适合正式多人协作。
2. SQLite + 后台单写入：可用于小规模内网，但必须由后台服务统一写入，客户端不能直接写数据库文件。

## 客户端改造

当前桌面 App 需要做这些调整：

- 去掉本机 `localStorage` 作为主数据源
- 去掉客户端内置账号密码
- 启动后连接内网后台
- 登录后按角色拉取权限和数据
- 保存项目、任务、日历、财务时调用后台接口
- 收到后台实时通知后刷新界面

## 发布方式

NAS 上建议维护两个目录：

```text
CrewFlow/
├─ Mac/
│  └─ CrewFlow.app
├─ Windows/
│  └─ CrewFlow.exe
└─ docs/
   └─ 使用说明.md
```

后台服务单独部署，不放在每个人的电脑上。
